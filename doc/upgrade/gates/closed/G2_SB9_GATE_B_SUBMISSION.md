## 3. 【核心】`TRANSPORT_RETRIES` 的 known-FAIL 對照

本 SB 最有價值的一組證據不是「740 天完成」，而是下面這個對照——
**它是真的跑出來的，不是推論**：

| `TRANSPORT_RETRIES` | 起點 | 取得天數 |
|---------------------|------|---------|
| 2 | 20260615 | **0**（SSL ×3） |
| 5（+ 遞增退避 5/10/20/40/60） | **同一個 20260615** | **105**，且該日**第一次嘗試就通過** |

### 為什麼會走到需要這組對照

`20260615` 跨兩段至少 4 次嘗試全敗，我一度想**再花一段請求去分辨**
「運氣差」與「該日期特殊」。

**複查方指出那個分辨不需要觀測，而且結構上不可能成立**：

> TLS 交握是對 `www.tpex.org.tw:443` 做的，**在任何 path 或 query 送出之前**；
> SNI 只帶主機名。**憑證驗證失敗的那一刻，伺服器根本不知道我們要問哪一天。**

真正的成因是**選擇效應**：每一段都從中斷點起跑，
所以每一次邊緣節點的隨機失敗都**必然**落在同一個日期上。

> **20260615 是失敗累積的地方，不是失敗的原因。**
> **一個看起來像訊號的數字，其實是取樣方式的產物。**

**衍生規則**：**段數是拿來計「邏輯進度停滯」的，不該拿去吸收 TLS 抖動。**
段四燒掉一整段只換到 1 個邏輯請求。

## 4. 本 SB 反覆出現的一類缺陷（八次）

**成因都是同一個：一個標籤說的事，和它實際量的事不是同一件。**
其中三次的更根本成因是**同一個概念有兩個實作**。

| # | 缺陷 | 指紋 |
|---|------|------|
| 1 | `extract_table` 重新實作了 `_find_market_table` 已有的能力 | 候選端點被判「不可用」，實為腳本讀不到 |
| 2 | 欄名帶尾隨空格，錨定樣式失配 | 失敗形式是「找不到表」，與「端點不可用」輸出相同 |
| 3 | 「成功」在文件（通過 C1~C6）與程式（C1 層級）有兩個定義 | 搜尋提前停止，帶日期參數的候選從未被測 |
| 4 | 傳輸層失敗被記成 C1 FAIL | 宣稱「端點不合契約」，而我們根本沒看到回應 |
| 5 | `evaluate()` 用精確比對 `_idx`，`extract_table` 用 `_match_fields` | 同檔兩套欄位對映；C4 FAIL 而端點八欄俱全 |
| 6 | 傳輸層重試規則未從端點驗證腳本傳播到取數腳本 | 取數第一個請求即死 |
| 7 | **`cur.rowcount` 在 `execute_values` 後是「最後一批」不是「插入數」** | 887 列全成功卻回報 87，**偽陽性宣稱 800 列被靜默丟棄** |
| 8 | 5xx 退避後的請求是裸 `requests.get`，不在傳輸層保護內 | **錯誤訊息對不上**（原始 SSLError 而非「重試 N 次後」） |

**第 7 項最值得記**：那是一個**寫來偵測「標籤與實際量的東西不同」的檢查，
自己就是那個病**。已改用 `RETURNING` + `fetch=True`，並於臨時庫實測對照
`RETURNING 887→0` vs `rowcount 87→0`。

**同型第九次出現在驗證指令本身**（2026-09-02，複查方指出）：
我用 `git diff --cached | grep -vc "^+#"` 宣稱「只改註解 = 0」，
**但該指令數的是「不以 `+#` 開頭的行」，而 diff 必然含 `diff --git`／`@@`／context 行——
它在任何真實 diff 上都不可能是 0**（實測給 48）。結論正確，但不是那個指令驗出來的。
已改用會失敗的寫法：`grep -E "^\+[^+]" | grep -vcE "^\+\s*#|^\+\s*$"`，
對本次 hook 註解 commit 給 **0**、對 `e2081c0`（真有程式碼）給 **389**。

> **⚠ 本段原寫 106，那是錯的** —— 106 是 `src/extractors/tpex_market_report.py`
> **單一檔案**的數字，`e2081c0` 五檔合計為 389
> （152 / 1 / 106 / 23 / 107）。結論不受影響（非 0 即證明該檢查會失敗，
> 389 只是更強），**但那是檔案層級的數字被寫成 commit 層級的**。
>
> **而它就出現在記錄「同型第九次」的這一段裡** ——
> **標籤說的範圍，和數字實際量的範圍不是同一個。**
