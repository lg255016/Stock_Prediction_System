## 1. 第 1 題：`SUCCESS_EMPTY` 的日子能不能進訓練

### 1.1 契約的字面答案：**能**

`FEATURE_REGISTRY.md` §5A.2 判定流程逐字：

```
if source_status == 'SOURCE_FAILED':
    → 該列在含情緒特徵的契約下排除訓練

elif source_status in ('SUCCESS', 'SUCCESS_EMPTY', 'SOURCE_DEGRADED'):
    → 依 §5A.3 對照表處理暖機期（成因 W）
```

**`SUCCESS_EMPTY` 與 `SUCCESS` 走同一個分支，不在排除之列。**

### 1.2 PO 的選擇偏誤論證成立，而且可以再強一點

> 排除空日等於只在「有人討論的日子」訓練，**而安靜是市場的常態。**

**再加一層**：空日的分佈**不是隨機的** —— 它與低關注度、低成交量、非事件期系統性相關。
排除它們不只是少了樣本，是**把整個「平靜狀態」的條件分佈從訓練集裡拿掉**，
而模型上線後遇到的多數日子正是那種日子。
**這與 §5A.4 禁止填補的理由是同一個形狀**：一個系統性地與市場無關的偏誤。

### 1.3 ⚠ 但判定流程有一個缺口：它只認得 W 和 F

§5A.1 自 **DEC-030（2026-08-31）** 起宣告**三種**成因：**W（暖機期）／F（來源失敗）／U（數學未定義）**。

**而 §5A.2 的判定流程只有兩個分支，沒有 U。**

> **本體改了、摘要沒改** —— §5A.1 的標題在 2026-09-05 才因同一個病補正
> （「本標題原寫『兩種』，而它自己的下一行寫的是『三者之一』」）。
> **那次補的是標題；判定流程沒有一起補。**

### 1.4 這個缺口正好落在空日：`sentiment_mean` 是 U，不是 W

§5A.1 的定義逐字：

| 成因 | 定義 |
|---|---|
| **W** | 資料**確實存在**，但時序視窗尚未累積足夠歷史 |
| **U** | 資料**齊備、視窗足夠**，但公式在該點**數學上未定義** |

**空日的取數是成功的（資料齊備），視窗也沒有問題 —— 缺的是文章本身。
而空集合的平均數在數學上未定義。** 這正是 U 的定義，不是 W 的。

**⚠ 但不是八欄都如此。逐欄查明，只有平均數型的會落到 U：**

| 欄位 | 空日的值 | 成因判定 | 依據 |
|------|---------|---------|------|
| `article_count` | `0` | **事實** | 空集合的**計數**是 0，**這是真的** |
| `bullishness_index` | `0.0` | **有定義** | `ln((1+0)/(1+0)) = 0`，Laplace 平滑使其在 `pos=neg=0` 有定義（`feature_aggregator.py:164-176`） |
| `agreement_index` | `0.0` | **有定義** | 公式**明文**「若 `Pos+Neg == 0`，定義為 `0.0`（無共識）」（`:178-194`） |
| **`sentiment_mean`** | **`0.5`** | ⚠ **U** | **空集合的平均數未定義。** `0.5` 是填補，不是計算結果 |
| `sentiment_3d_ma` / `5d_ma` | `0.5` | ⚠ **U 的傳播** | 由已填補的 `sentiment_mean` 再計算 |
| `sentiment_lag_1` / `lag_2` | `0.5` | ⚠ **U 的傳播** | 同上 |

> **這個區分是承重的**：`bullishness_index = 0.0` 與 `agreement_index = 0.0`
> **是公式在該點的真值**，不是編出來的；`sentiment_mean = 0.5` **是編出來的**。
> **把兩者一起說成「空日的特徵都是假的」會誇大，一起說成「都合法」會漏掉真正的問題。**

⚠ **上表進契約**【PO 2026-09-07 裁決】：隨 D5 一併寫入 `FEATURE_REGISTRY.md` §5A，
**與 §5A.2 的 U 分支同一次落地**。理由：**混為一談兩個方向都會錯。**

### 1.5 填補值與真值的碰撞 —— 實測，不是推論

真實庫 `daily_ml_features`（137 列）：

```
sentiment_mean = 0.5 的列： SUCCESS_EMPTY 99 列  +  SUCCESS 2 列  =  101 / 137 = 73.7%
```

> ⚠⚠ **有 2 列是真的觀測到 0.5。**
> **模型看到 `0.5` 時，無法分辨「那天真的中性」與「那天沒有文章」。**

§5A.1 早就寫過這個危險，只是寫的是 F 與 W 的碰撞：

> 「這兩者在數學上可能落到同一個值……但語意完全不同……
> 等同於讓模型讀到一個從未觀測到的訊號」

**同一個碰撞在 `SUCCESS_EMPTY` 與 `SUCCESS` 之間也存在，而契約沒有寫。**

### 1.6 ⇒ 第 1 題的建議答案

### 1.7 ⇒ 這如何改變「門檻」的定義

若空日可訓練（建議 1），**覆蓋率就不決定面板大小，它決定的是
「情緒特徵有多少比例是實際觀測、多少比例是填補或 NULL」。**

> **門檻管的是特徵的資訊量，不是樣本數。** 這使第 2 題的推導方向必須改變 —— 見 §2.4。

## 2. 第 2 題：由 §3.3 反推最低面板

### 2.1 Fold 算術（`PURGED_WALK_FORWARD_SPEC.md` §3.1 + §3.3）

參數預設值（§3.1）：`train_window_size = 60`、`test_window_size = 20`、
`step_size = test_window_size = 20`、`label_horizon` = 1（T+1）或 5（Triple-Barrier）。

`rolling` 模式下第 `i` 折（自 0 起）：`train = [i·20, i·20+60)`、`test = [i·20+60, i·20+80)`。
§3.3 要求**最少 3 個完整 Fold**，即第 2 折的測試窗需完整：

```
N ≥ 2×20 + 60 + 20 = 120 個交易日
```

Purge 移除訓練尾端 `label_horizon` 天（§2.2、§3.2），使每折實際訓練樣本為
**59 天（T+1）或 55 天（Triple-Barrier）**，**但不改變 N 的下界。**

**交叉驗證（本式不是只在紙上成立）**：`PROJECT_STATUS.md` §0.5 #16 記載的實測為
「740 個交易日、`rolling(60, 20)` → **34 個 fold**」。
以本式反算：`⌊(740−60−20)/20⌋ + 1 = 34` —— **相符**。
同式在 N = 120 時得 `⌊(120−80)/20⌋ + 1 = 3` 折。

> **這個核對不是形式** —— 兩個數字由不同的人在不同時間分別得出，對上了才算數。

### 2.2 ⚠⚠ `min_train_size`：**本檔初版寫錯了，這裡是更正**

**初版寫「`min_train_size` 在全份規格中沒有被賦值……這一格是空的」。**

**那是錯的，而且錯在只讀了規格、沒讀已登錄的分析。**

`src/ml/time_series_split.py:94` **有推導它**：

```python
self.min_train_size = max(1, self.train_window_size - self.label_horizon)   # 預設 = 59
```

`:50-52` 的 docstring 逐字寫明理由：
「**即容許正常 Purge 造成的縮減，但不容許 Purge/Embargo 疊加造成的額外縮減**」。

而 `PROJECT_STATUS.md` **§0.5 #16（2026-09-02 登錄）已經把整件事量測完了**，
其結論比「空格」嚴重得多：

| `embargo_days` | fold 數 | `min_train_size` 檢查 |
|---|---|---|
| **0**（§3.1 預設、嚴格 WF） | **34** | **全部 59，無一低於門檻 —— 通過，但零訊號** |
| 1 / 5 / 10 | **2** | —— **低於 §3.3 自己要求的 ≥ 3** |

> **問題不是判準空著，是判準與情境相依而情境沒被寫出來。**
> **在 §3.1 的預設下，`min_train_size` 檢查恆真 —— 那是 `CLAUDE.md` §9A.1
> 「結構上無法失敗的檢查不是檢查」的同一個形狀。**

§0.5 #16 另記載：該衝突**僅存在於 `mode='rolling'`**；`expanding` 在各 embargo 值下皆維持 34 折，
**但守衛在該模式下同樣近乎失明** —— `embargo=20` 時最後一折訓練天數掉到 80 天（少 89%），
而 `min_train_size = 59` **因 80 > 59 完全沒有反應**。

⚠ **且 §0.5 #16 明文禁止一條捷徑**，本檔照錄：

> `expanding` 維持 34 折這個事實**用於界定問題範圍，不得作為「改用 expanding」的理由** ——
> rolling 與 expanding 的選擇是**建模決定**，
> **不得由「哪個設定能讓 fold 數過關」決定**。

#### ⇒ D1 的正確形狀

**不是「填一個數字」，是 §0.5 #16 已列明的三件事**：
(1) rolling 還是 expanding（**建模決定，需 regime shift 證據**）；
(2) `embargo_days = 0`（嚴格 WF）還是 CV 場景；
(3) 若 (1) 選 rolling 且 (2) 選 `embargo > 0`，`min_train_size` 覆寫成多少。

**本檔不解這三件事** —— 它們的觸發條件是「Gate 3 啟動前」，且已綁事件登錄。

⚠ **對本提案的實質影響**：若走嚴格 WF（`embargo = 0`），
**「`min_train_size` 檢查通過」不得被當成資料量充足的證據** —— 它在該情境下恆真。
**覆蓋率門檻不能靠它背書。**

### 2.3 Holdout 與 3 年要求：**兩個下界不一致，且較大的那個不是推導來的**

| 來源 | 下界 |
|------|------|
| Fold 算術（§2.1） | **120 個交易日** |
| ＋ Holdout 6～12 個月（§3.3） | **約 246～372 個交易日** |
| §3.3「歷史深度至少 3 年」 | **約 756 個交易日** |

> ⚠ **3 年的要求比 fold 算術嚴格 2～3 倍，而它不是從 fold 算術推出來的。**
> 它多半是為了涵蓋不同市場 regime —— **但規格沒有寫理由。**

#### D2 裁決【PO 2026-09-07】：**不是二選一**

**初版把這寫成「兩者衝突時以哪個為準」—— 那個框架本身就錯了。**

| | 地位 |
|---|------|
| **「3 年」** | **維持權威** —— 它在已核准的 Gate 0 交付物裡（`CLAUDE.md` §0.2 優先序第 3 級）。**改它需要 ADR，不是在門檻提案裡順手選掉** |
| **120 交易日** | **記為算術下界** |

> **下界的用途是「低於它一定不行」，不是「到了它就夠」。**
>
> **120 日 → Gate 3 實驗可以開始跑的最低面板；**
> **3 年 → Gate 3 結論可以成立的面板。**

若 Gate 3 設計時認為 3 年過嚴，**屆時開 ADR 論證** —— 不在本檔處理。

## 3. 第 3 題：門檻是逐標的的，不過的標的怎麼辦

### 3.1 先決：覆蓋率門檻用什麼當錨

既然推導不出來（§2.5），**候選錨有三個**：

| 錨 | 內容 | 評估 |
|---|------|------|
| **(a) 統計可估性** | 每個**訓練窗**內至少要有 K 天實際觀測，情緒特徵才可估 | 可計算，但 K 仍需一個來源 |
| **(b) 預測力對照**（**建議**） | **有／無情緒特徵的 walk-forward 對照**；情緒特徵只有在改善時才保留 | **與 PO 對 (B) 總經詞已裁定的標準完全一致：「用預測力說話，不用合理性說話」** |
| **(c) 變異數下限** | 要求 `sentiment_mean` 在每個訓練窗內的相異值／變異數超過下限 | 直接針對 §1.5 的「近乎常數」問題，可作為 (b) 的前置篩 |

**建議：(b) 為決策規則，(c) 為前置篩，(a) 併入 (c)。**

> **理由不是 (b) 比較嚴謹，是本專案已經對同型問題做過這個選擇。**
> (B) 的兩個候選假設用 walk-forward 有無對照決勝負；
> **覆蓋率門檻用同一把尺，才不會出現「總經詞要證明預測力、情緒覆蓋率卻靠拍板」的雙標。**

⚠ **(b) 的門檻數字必須在回補資料到位後量測產生，不得在本檔設定。**

⚠ **粒度必須是逐標的 × 逐折，不是逐標的整體** ——
一檔股票可能 2025 年覆蓋充足、2023 年完全沒有，
**而整體平均會把這件事藏起來**（同 `PRE_G3_01` §5.2「合計不等於逐標的」的教訓，**再降一層**）。

#### D3 裁決【PO 2026-09-07】：**採「預測力對照」**，另加第三項依據

> **一個門檻其實是三個瓶頸。**

§2.4 量到的三格成本互不相同（台股價格**零請求**、NVDA 需**新來源**、情緒需**回補**）。
**單一覆蓋率門檻會把這三件事壓成一個數字，而它們沒有一個能被那個數字回答。**
預測力對照天然分得開：**對照臂的差異來自哪一格，實驗設計時就決定了。**

⚠ **`min_train_size` 不能替門檻背書**（§2.2 末段）—— 嚴格 WF 下它恆真。

### 3.2 不過門檻的標的：四個選項與代價

| # | 選項 | 代價 |
|---|------|------|
| **1** | **剔除該標的** | ⚠ **會重現宇宙層的選擇偏誤** —— 依「討論度」剔除標的，等於只研究被討論的股票。**這正是 2026-09-07 裁決不寫 `entity_mapping` 的同一個理由** |
| **2** | **降級：該標的只用非社群特徵** | 兩個特徵空間並存，跨標的不可共用同一模型；且「有情緒的標的表現較好」會**無法歸因**於情緒還是歸因於標的本身 |
| **3** | **保留全部標的 ＋ 明示的可得性指標**（**建議**） | 新增一欄（如 `sentiment_observed`）讓模型可以學會忽略；⚠ **這是 29 欄契約的變更**，需 ADR |
| **4** | **情緒欄 NULL ＋ 只用容忍 NULL 的模型** | ⚠ 使 `LogisticRegression` 出局（**實測，見 §1.6**）——四模型剩三個，且失去唯一的線性可解釋基準線。⚠ `CLAUDE.md` §13.3 已記載 host 上「四模型實際只有兩種實作」的前例，**那次是靜默發生的；這次至少是明示的** |

**本檔初版建議選項 3 —— 已被 §3.3 的裁決推翻。**

### 3.3 ⚠ D4 裁決【PO 2026-09-07】：**不採選項 3，改採選項 4**

#### 裁決依據 —— PO 原則，逐字照錄

> 「所有的模型訓練一定要基於事實⋯⋯情緒文章在大多數日子都是空日，
> 就跟股票股價其實大部分都在盤整，對市場的人這種盤勢就不會有什麼情緒；
> 情緒強烈的時候，通常股價的波動就比較大。
> 我們建立的特徵值用 ML 去訓練，一定要可以與現實對應。
> **如果模型不適用，代表這個模型不適合這個問題，我們應該換模型，
> 而不是把特徵改成與現實不相符或無法解釋而讓模型可以訓練。**」

#### 落地形狀

| 層 | 內容 |
|---|------|
| **儲存層** | 空日 `sentiment_mean`（及 4 個衍生欄）= **NULL（成因 U）** —— 即 D5 |
| **模型層** | **不填補、不加指標欄**。RandomForest／LightGBM／XGBoost **原生處理 NaN**（§1.6 實測），**缺失方向由模型自己學** |
| `sentiment_observed` 欄 | **不做** —— NaN 本身就是訊號，且 `article_count = 0` 已是模型看得見的事實 |

> **模型自己決定怎麼理解安靜，而不是我們餵它一個編出來的中性。**

⚠ **這推翻了初版的選項 3。** 初版的理由是「不縮減模型集合」——
**而那是把「保住四個模型」放在「特徵要對應現實」之上。順序反了。**

#### `LogisticRegression` 不是出局，是換位置

**D3 的預測力對照本來就需要一條「無情緒特徵」的對照臂**
（價量特徵在暖機後無 NULL）—— LR 去那裡當 baseline，
同時滿足 `CLAUDE.md` §14 對 ML 任務「結果能與合理 baseline 比較」的要求。

> **「換模型」在這裡不是丟掉 LR，是把它放到它能誠實工作的位置 ——
> 而那正是實驗設計本來就缺的一角。**

#### ⚠ 順帶產生一個可驗假設，寫進 D3 的實驗清單

PO 的盤整類比**是可檢驗的**：

> **若情緒強度與波動相關，空日應與低波動日共現。**

- 身分：**`HYPOTHESIS`**（`CLAUDE.md` §8）—— **不是已知事實，不得當作設計前提**
- 驗證：Gate 3，以 `volatility_5d` / `volatility_20d` 對照空日分佈
- ⚠ **它只有在空日被誠實存成 NULL 時才驗得了** —— 填成 0.5 之後，
  「空日」這個事實在特徵表裡就消失了

⚠ **D4 與 D5 同一輪落地**，兩者都動 29 欄契約的語意，分開做會產生一次中間狀態。
