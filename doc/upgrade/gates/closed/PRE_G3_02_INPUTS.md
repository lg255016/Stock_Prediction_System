## 3. 三項結構性登記【PO 2026-09-07 裁決】

### 3.1 `entity_mapping` 是雙用途表 —— 設計債

| 用途 | 位置 |
|------|------|
| 路由（關鍵字 → 股票，讀取時套用） | `db_writer.py:600-606` |
| **宇宙定義**（決定抓哪些股票的價格） | `db_writer.py:404-413` → `main_etl_pipeline.py:611` |

**登記內容**：Gate 3 接軌 PIT Universe 時，**宇宙定義必須改從 `universe_snapshots` 取，
`entity_mapping` 退回純路由**。**兩者分離是 Gate 3 的前置設計項。**

> **一張表叫 `entity_mapping`，不代表它只做 entity mapping。**
> 這次是在寫入前先查了寫入的後果才發現的 —— **查的是後果，不是名字。**

### 3.2 `ai_discovered` 關鍵字有一半沒有對映 —— 根因在寫入路徑

`trend_discover.py` 的 `trends` 分支同時寫關鍵字與題材對映；
**向下相容的 `keywords` 分支只寫關鍵字**。
而 **`entity_mapping` 沒有任何 runtime 寫入者**（全 repo 僅 `schema.sql:143` 的種子）。

> **AI 探索出來的個股名，在結構上永遠不可能成為 entity 對映。**

**登記內容**：修 `trend_discover.py` **屬另案，不在 `PRE-G3-02` 範圍**。
本項只確保 `PRE-G3-02` 知道缺口不是偶發疏漏，**而是每次探索都會再生一次**。

⚠ **本輪未修改 `trend_discover.py` 任何一個字元。**

### 3.3 覆蓋率的分母必須是特徵宇宙

見 §1 第 3 項。**登記內容**：`PRE-G3-02` 的任何覆蓋率結論，
若分母取自 `entity_mapping` 或 `theme_stock_mapping` 的列數，**該結論無效**。

### 5.4 ⚠ future-dated（段 4 子形狀 c）有獨立於 wrap-rule 的價值


> 它攔的不是「年份推論錯」，是「留言不可能來自未來」，兩者是不同的保護對象。
