## 0. 為什麼是試點而不是全量

B0 給了**深度**（11.66 年，下界），但它給**產量**的只有 **n = 1 命中 / 145 篇**。

```
命中率 1/145 = 0.69%     Wilson 95% CI：0.12% ~ 3.80%   ← 跨度 30 倍
```

> **一個 30 倍跨度的估計，不該拿來支撐一個上萬請求的承諾。**
> **這與 B0 本身是同一條紀律：不要在量到之前先猜。**

**試點用全量 2% 的成本，把 n = 1 的抽樣換成窮盡量測。**

## 1. ⚠ 規模換算：**複查方的「200 頁 ≈ 1 年」與 B0 的資料不符**

複查方 §三 寫「試點範圍：最近 **200 頁**（約 **1 年**）」。**用 B0 的實測換算，那是約 2 個月。**

| 依據 | 計算 |
|------|------|
| B0 實測 `N=5182` 的最舊文章 = `2022-06-28` | 5,182 頁 / 1,531 天 |
| 近期速率 | **≈ 1,236 頁／年** |
| **200 頁** | **≈ 59 天 ≈ 1.9 個月** |
| 涵蓋 **1 年**需要 | **≈ 1,236 頁** |

**本提案採 200 頁（≈ 2 個月），並把「1 年」的說法更正掉** ——
**不是縮小範圍，是原本的頁數與時間對不起來。**

### ⚠ 而查證過程中撞到一個更重要的東西：**看板速率跨 11 年變動 60 倍**

B0 的八個抽樣點兩兩相鄰換算：

| 區間 | 速率 |
|------|------|
| 2015-01 → 2017-07 | **32 頁／年** |
| 2017-07 → 2019-04 | 93 頁／年 |
| 2019-04 → 2019-08 | 986 頁／年 |
| 2020-03 → 2021-02 | 1,497 頁／年 |
| **2021-02 → 2022-06** | **1,852 頁／年** |

> **2015~2017 與 2021~2022 差 58 倍。**

**這改變了回補的成本結構**：

| | 頁數 | 涵蓋 |
|---|------|------|
| `N=81` → `N=324` | **243 頁** | **2015-01 ~ 2019-04（4.25 年）** |
| `N=5182` → `Nmax` | **5,182 頁** | 2022-06 ~ 2026-09（4.2 年） |

**同樣四年多，一邊 243 頁、一邊 5,182 頁 —— 差 21 倍。**

> **「往回 11.66 年」聽起來昂貴，而它的前四年其實只要 243 頁。**
> **真正貴的是最近幾年，而那正是我們已經有能力每日累積的部分。**

⚠ **本節不推導回補策略** —— 那是全量提案的事。**本節只記下這個事實，
因為它會改變全量提案該怎麼寫，而全量提案要等試點的數字。**

### ⚠ 硬上限 300 的理由與行為

**若命中數超過 100（即密度 > 2.5%），達到 300 即停止並回報** ——
**不繼續、不提高上限。** 那代表 B0 的 0.69% 嚴重低估，
**而「預算被撞破」本身就是要送審的發現。**

## 4. 判準【觸網前寫死，跑完只做比對】

| # | 判準 | 什麼輸入會讓它 FAIL |
|---|------|-------------------|
| **P1** | 請求數 `<=` 300 | 超過即代表節流或上限失效 |
| **P2** | **逐頁記錄 HTTP 狀態**，404 的頁碼清單完整列出 | 只記總數而不記頁碼 → 無法檢驗單調性 |
| **P3** | **單調性窮盡檢驗**：200 頁中若有 404，其分佈必須被列出；**不得只回報「有 N 個」** | 只給總數 |
| **P4** | `validate_comment_bounds` 非空的文章**整篇拒寫**，且拒寫清單可觀測 | 為了提高產量而放寬邊界 → **明文禁止** |
| **P5** | `market_articles` 新增列數 == 命中數 − 已存在的 URL 數 | 去重或 upsert 失效 |
| **P6** | `article_comments` 列數 == 各篇 `total_comments` 之和（**扣除被拒寫的篇**） | 解析器與計數器不一致（W4 的規模版） |
| **P7** | **既有 332 列 `market_articles` 與 38 列 `article_comments` 不得被改動** | 回補動到既有資料 |
| **P8** | `daily_ml_features` 指紋不變（137 列） | 回補意外觸發特徵重算 |

⚠ **P4 是本試點的紀律核心**：

> **回補不得為了量而放寬 `validate_comment_bounds`。**
> **一個「為了讓資料進得去」而放寬的邊界檢查，比沒有檢查更糟 ——
> 它會讓後續所有人以為那些資料通過了檢查。**

## 6. 寫入目標：**隔離臨時 DB**【決策點 3，PO 2026-09-06 推翻其原指示】

### 6.1 為什麼改

PO 原指定「試點寫真實庫」，**在我算出規模之前**。兩個當時不存在的事實：

1. **規模**：當時以為試點 ≈ 1 年；實際是 **2 個月**。
   > **一段孤立的 2 個月回補資料進真實庫，會製造一個覆蓋斷崖**
   > （2 個月有、之前之後皆無），**而特徵管線會如實消費它。**
2. **待決問題**：「PTT 密度夠不夠支撐 Gate 3」正掛在 `PRE-G3-02`。
   > **若答案是不夠，真實庫裡的試點資料就要移除 —— 那是需要授權的 destructive 操作。**
   > **先寫臨時 DB，讓「不採用」的成本是丟棄一個容器，不是一次 `DELETE`。**

⚠ **「昂貴的部分是觸網」這個邏輯不受影響**：臨時 DB 持久化了抓到的東西，
**日後匯入是 DB 層搬運，不必重抓一個位元組。** SB9 的先例（分段後才匯入）同構。

### 6.2 四項條件

| # | 要求 |
|---|------|
| 1 | 臨時 DB 以 **`apply_migrations.py` 全套重放**建 schema —— **不是手工 `CREATE`**。**匯入時 schema 才保證同構** |
| 2 | `DB_HOST`／`DB_PORT` 覆寫 + **綁定確認先印再寫**（`CLAUDE.md` §13.4 的既有義務） |
| 3 | **寫入路徑用生產同一條**（`validate_comment_bounds` 拒寫整篇 + 可觀測錯誤照常）—— **換目標不換路徑** |
| 4 | 臨時 DB 的資料**保留到全量決策做出為止**，**不隨手拆** |

### 6.3 ⚠ RISK-013 的落點隨之改變 —— **是搬家，不是免除**

| 步驟 | RISK-013 |
|------|---------|
| **本試點**（寫臨時 DB） | **只需第 2 項的綁定確認** —— 不碰真實庫 |
| **匯入真實庫**（若核准，另案） | **完整三項**：綁定確認 + `pg_dump` + **實測還原** |

⚠ **`article_comments` 屆時有資料** —— migration 008 當時免 `pg_dump` 的理由
（目標表 0 列、回滾是單一 `DELETE`）**在匯入那一步不成立**。

**回滾**：本試點的回滾是**丟棄臨時容器**；匯入後的回滾才需要 `DELETE` 與 PO 授權。

| # | 內容 |

| 6 | ⚠ **便宜的那四年正是時代混淆最重的四年** —— 見下 |

### ⚠ 第 5 項：兩條線在這裡匯合

**RISK-021 記的是「適用對象」**：PTT 是台灣的論壇，
**用它的情緒去預測美股標的，相關性從來沒有被檢驗過**。

**本試點量的是「密度」**：一檔標的一年有幾天有文章。

> **兩者指向同一個更大的問題 —— 「PTT 這個資料源夠不夠支撐 Gate 3」。**
> **而那個問題的位置是 `PRE-G3-02`（RISK-015），提問人是 PO** ——
> RISK-015 一開始就是 PO 自己提的擔憂。

**本提案不回答它**（n 不足，且超出範圍），
**但把兩條線寫在同一節，讓它們在該匯合的地方匯合，而不是靠下一個人自己想起來。**

### ⚠ 第 6 項：便宜的頁 ≠ 有用的資料

§1 量出 **2015–2019 的四年多只要 243 頁**，看起來是回補最划算的一段。

> ⚠ **而那正是關鍵字時代混淆最重的四年。**
> **頁數便宜 ≠ 資料有用 —— 243 頁買到的命中率，會被「CoWoS 當年不存在」系統性壓低。**

**`PRE-G3-02` 讀那批資料時必須知道這件事**，否則會把「當年沒人討論這個題材」
讀成「當年這檔股票沒有討論度」。**兩者不是同一回事。**
