## Risk Acceptance Criteria

以下準則定義哪些風險層級需要 PO 決策才能繼續推進：

1. **High 嚴重度風險** — 必須經 PO 審查並明確簽核（Accept / Mitigate / Defer）後，相關 Gate 才可進入實作。未經 PO 決策的 High 風險將阻擋對應 Story 的開工。

2. **Medium 嚴重度風險** — 開發團隊可依緩解方式自行推進，但須在 Gate Review 時向 PO 報告狀態更新。若觸發條件成立且緩解方式失效，則升級為 High 並回到準則 1。

3. **Low 嚴重度風險** — 開發團隊自行管理，記錄於風險清冊即可。僅在狀態變更時於 Sprint Review 中提及。

4. **證據標籤為 NOT VERIFIED 的風險** — 無論嚴重度，必須在對應 Gate 開始前完成驗證，將標籤更新為 OBSERVED、HYPOTHESIS 或 RESOLVED。驗證結果若升高嚴重度，適用上述對應準則。

5. **跨多個 Gate 的風險**（如 RISK-001）— 須在最早影響的 Gate Review 中首次審查，後續 Gate 追蹤狀態變化。

6. **升級門檻** — 任何風險若同時滿足以下條件，自動升級一個嚴重度等級並通知 PO：
   - 觸發條件已成立
   - 緩解方式執行後仍無法將影響控制在可接受範圍
